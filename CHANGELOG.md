# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.1] - 2026-09-30

### Added

- Sysadmin page at `/ckan-admin/apidocs/` (tab **API documentation** under
  `/ckan-admin/`) to edit the OpenAPI document served by the documentation.
  The document is prefilled with the generated one, is edited as JSON or YAML
  and is stored in the new `apidocs_schema` table, from where it is served by
  the documentation endpoints instead of the generated document. The
  **Format** action normalizes JSON/YAML, **Load generated document** fetches
  the generated document, and **Reset to generated** removes the stored one.
- Actions managing the stored document, all sysadmin-only:
  `apidocs_schema_show`, `apidocs_schema_update` and `apidocs_schema_delete`.
- `apidocs_schema_state` table with a version counter, so every worker process
  picks up a saved document without waiting for `ckanext.apidocs.cache_ttl`.
- Migrations of the extension (`ckan db upgrade -p apidocs`) creating both
  tables. They have to be applied after upgrading an existing installation.
- The stored document is saved and served with every object key in
  alphabetical order. `JSONB` does not preserve key order, so the order is
  restored on read; alphabetical `paths` also make the operations of every
  HTTP method section of the Swagger UI alphabetical, since the UI lists them
  in the order of `paths`.
- `apidocs export --generated` option, exporting the document generated from
  the registered actions instead of the stored one. Without the flag the
  stored document is exported when there is one.

### Changed
- Dependencies are declared only in `pyproject.toml`: `PyYAML` under
  `[project] dependencies` and the dev tools under the `dev` extra. The
  `requirements.txt` and `dev-requirements.txt` files were removed.

## [0.1.0] - 2026-09-20

First production release. Compatible with CKAN 2.11 and 2.12.

### Added

- Configuration options, declared in `ckanext/apidocs/config_declaration.yaml`
  and loaded through the CKAN `config_declarations` blanket, read lazily:
  `ckanext.apidocs.base_path`, `ckanext.apidocs.openapi_version`,
  `ckanext.apidocs.enable_api_methods`, `ckanext.apidocs.title`,
  `ckanext.apidocs.description`, `ckanext.apidocs.spec_version`,
  `ckanext.apidocs.token_header`, `ckanext.apidocs.cache_ttl`,
  `ckanext.apidocs.require_login`, `ckanext.apidocs.include_extensions`,
  `ckanext.apidocs.exclude_extensions`, `ckanext.apidocs.sysadmin_only`,
  `ckanext.apidocs.allowed_users` and the `ckanext.apidocs.ui.*` group.
- `ckanext.apidocs.sysadmin_only` setting, allowing only sysadmins to open the
  documentation page and the generated documents. Enabling it also requires
  authentication (anonymous visitors are redirected to the login page) and it
  takes precedence over `ckanext.apidocs.allowed_users`.
- `ckanext.apidocs.allowed_users` setting: a space separated list of usernames
  that are the only ones allowed to open the documentation page and the
  generated documents. Setting it also requires authentication (anonymous
  visitors are redirected to the login page), even when
  `ckanext.apidocs.require_login` is disabled.
- `IApidocs` interface, so other extensions can modify the generated document
  and add badges to individual actions.
- Caching of the generated specification, with `ETag` and `If-None-Match`
  support on the JSON and YAML endpoints.
- `/api/docs/openapi.json` and `/api/docs/openapi.yaml` aliases.
- `apidocs export` command options `--base-path` and `--version`, plus proper
  error reporting when the target file cannot be written.
- Badges (`x-badges`) are rendered next to each action path in the UI.
- Tests for the specification builder, the docstring parser, the views, the
  CLI, the plugin and the `IApidocs` interface.

### Changed

- Config options are declared in `config_declaration.yaml` instead of an
  `IConfigDeclaration` implementation, so they can be described, validated and
  generated by the CKAN configuration tooling.
- The specification is rebuilt from scratch on every build; configuration is
  evaluated per request instead of at import time.
- HTTP methods of plugin actions are inferred from the action name and the
  `side_effect_free` marker, so they are no longer all documented as `POST`.
- Operations now document `security`, `operationId`, error responses, and
  parameter types parsed from `:type:` directives (including the `:type:`
  variant used in CKAN's own docstrings).
- The documentation page keeps the theme assets of the site (`{{ super() }}`)
  and loads its CSS and JS from the standard CKAN asset blocks.
- Packaging metadata moved to `pyproject.toml`; `namespace_packages` removed,
  so modern setuptools versions are supported without pins.
- The vendored Swagger UI bundle is trimmed (duplicate bundle and source maps
  removed) and documented in `ckanext/apidocs/assets/THIRD_PARTY_LICENSES.md`.
- CI runs the test suite against CKAN 2.11, 2.12 and `master`, plus Ruff and
  Mypy.

### Removed

- Example scaffolding inherited from the extension template: the
  `apidocs_example` and `example_get_sum` actions, their auth/schema/validator
  registrations, the `example` CLI group, the static `public/ckanapi.json`
  specification and the `example_required` validator.
- The unused `swagger-ui.js` bundle, all vendored source maps and the dead
  `data-module="swagger-badges"` placeholder in the template.

### Fixed

- `apidocs export` no longer crashes: the command passed arguments that
  `build_openapi_spec` did not accept.
- The generated specification no longer leaks paths between calls through
  module level state.
- `:returns:`/`:rtype:` sections are no longer appended to the last documented
  parameter.
- `ckan.authz` is imported from its real location instead of relying on
  `ckan.logic.authz` being exported as a side effect.
- `ckanext.apidocs.include_extensions` and `ckanext.apidocs.exclude_extensions`
  were ignored when the document was built from the configuration: only the
  explicit `build_openapi_spec()` arguments were honoured, so the actions of an
  excluded extension kept showing up.
- The summary of an action whose docstring wraps over several lines now holds
  the whole first paragraph instead of leaking the wrapped part into the
  description.
- Errors raised by plugins during action discovery are logged instead of being
  silently swallowed.
